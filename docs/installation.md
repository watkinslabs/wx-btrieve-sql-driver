# Installation

## Prerequisites

- Windows (32-bit; tested on Windows 10 LTSC x86)
- SQL Server reachable from the machine
- NTVDM enabled (required to run DOS applications)

---

## Recommended: use the installer from a release

Download `wlbtr-installer-vX.Y.Z-windows-i686.exe` from
[Releases](https://github.com/watkinslabs/wx-btrieve-mssql-driver/releases/latest)
and run it as Administrator. The installer:

1. Creates `C:\WatkinsX\bin\` if it doesn't exist.
2. Drops the embedded `wxbtrv.dll` into `C:\Windows\System32\`.
3. Drops the embedded `wxbtrv.sys`, `db_config.exe`, and `btr-import.exe`
   into `C:\WatkinsX\bin\`.
4. Patches `C:\Windows\System32\config.nt`: adds the
   `DEVICE=C:\WatkinsX\bin\wxbtrv.sys` line and removes any existing
   `BTRDRVR.SYS` entry.

After the installer runs, skip to **Step 3 — Build the SQLite config
database** below to wire up SQL Server credentials and import schemas.

The remaining steps in this document describe the manual install path —
useful when developing wlbtr itself or running a local debug build.

---

## Manual install

### Step 1 — Create the install directory

```bat
mkdir C:\WatkinsX\bin
```

### Step 2 — Copy files

Two files need placement in specific directories:

```
C:\Windows\System32\wxbtrv.dll   ← built from crates/wxbtrv (target: i686-pc-windows-gnu)
C:\WatkinsX\bin\wxbtrv.sys       ← built from crates/wxbtrv-sys (NASM, DOS binary)
```

**`wxbtrv.dll` must live in `C:\Windows\System32\`.** NTVDM loads VDDs with
`LoadLibraryExA` + `LOAD_LIBRARY_SEARCH_SYSTEM32`, which ignores absolute
paths and only searches System32. Any other location silently fails
(`RegisterModule` returns CF=1 and INT 7B is never hooked).

The following native tools go wherever is convenient (typically
`C:\WatkinsX\bin\`, which should be on PATH):

```
db-config.exe     ← built from crates/db-config    (native Windows binary)
btr-import.exe    ← built from crates/btr-import   (native Windows binary; for flat-file migration)
```

See [Building](building.md) for how to produce these files.

## Step 3 — Build the SQLite config database (both install paths)

Run `db-config.exe` from `C:\WatkinsX\bin\`:

```bat
cd C:\WatkinsX\bin

rem Create empty database
db-config.exe init

rem Import all INT files (table schemas) — use -r for recursive
db-config.exe import-int -r G:\pacific G:\canada J:\advdata

rem Set SQL Server connection (overrides anything from INT files)
db-config.exe set-connection --server 10.0.0.231 --database GCanada --user sa --password yourpass

rem Verify
db-config.exe list
db-config.exe show-config
db-config.exe test-connection
```

Each table's `db_name` comes from the `DATABASE_SPACE_NAME` field in its INT
file. The `--server`/`--user`/`--password` from `set-connection` apply to all
tables regardless of what the INT files say.

`wxbtrv.db` is looked up at runtime in this order (see
`wxbtrv-core::sqlite_meta::find_sqlite_db`):

1. `WXBTRV_CONFIG_DIR` environment variable
2. Current working directory
3. Directory containing `wxbtrv.dll` (System32 on a normal install)
4. The `WXBTRV_CONFIG_DIR` baked in at compile time
5. `C:\WatkinsX\bin` (production default)

For a standard install leave the database in `C:\WatkinsX\bin\wxbtrv.db` and
no environment variables are needed.

### Step 4 — Update CONFIG.NT (manual only)

Edit `C:\Windows\System32\config.nt` as Administrator. Add or replace the
Btrieve device line:

```
DEVICE=C:\WatkinsX\bin\wxbtrv.sys
```

Remove any existing `DEVICE=...btrdrvr.sys` or `DEVICE=...BTRDRVR.SYS` line.

Minimal `config.nt` for reference:

```
dos=high, umb
device=%SystemRoot%\system32\himem.sys
files=40
DEVICE=C:\WatkinsX\bin\wxbtrv.sys
```

## Step 5 — Kill NTVDM and test (both install paths)

```bat
taskkill /F /IM ntvdm.exe
```

Then launch the DOS application normally. On the first Btrieve call:
1. NTVDM reads `config.nt`, loads `wxbtrv.sys`
2. `wxbtrv.sys` fires BOP 59h → NTVDM loads `wxbtrv.dll` from `System32`
3. `wxbtrv.dll::VDDInitialize` runs and opens `wxbtrv.db`
4. INT 7B calls flow through BOP 58h → `VDDDispatch` → `wxbtrv-core` → SQL Server

## Migrating from Btrieve flat files (.B)

**`btr-import`** reads `.B` files directly, decodes records using the field
definitions stored in `wxbtrv.db`, and bulk-inserts into SQL Server.

Before running `btr-import` the schemas must be in `wxbtrv.db`. There are
two ways to get them there depending on what you have available.

---

### Option A — You have INT files

INT files are sidecar schema files (one per table, extension `.INT`)
generated by earlier Btrieve tooling. They contain complete field
definitions: names, types, offsets, lengths, indexes, and connection details.

```bat
db-config init
db-config import-int -r G:\pacific G:\canada J:\advdata
db-config set-connection --server 10.0.0.5 --database GCanada --user sa --password ...
db-config list        ← verify all tables imported
```

Then migrate:

```bat
btr-import import-dir --create G:\data
```

---

### Option B — No INT files; only .B files

`db-config analyze-b` reads the File Control Record (FCR) inside each `.B`
file and bootstraps a schema in `wxbtrv.db`. It automatically extracts record
length, page size, key structure, field types, and offsets for all
key-segment fields. Non-key fields must be added manually with `add-field`.

```bat
db-config init
db-config set-connection --server 10.0.0.5 --database GCanada --user sa --password ...

rem Bootstrap each table from its .B file
db-config analyze-b G:\data\BKGLTRAN.B
db-config analyze-b G:\data\BKGLMAS.B
rem ... repeat for each table

rem analyze-b tells you how many record bytes are unaccounted for.
rem Add the remaining non-key fields manually:
db-config add-field BKGLTRAN --num 5 --name DESCRIPTION --type 0 --length 30 --offset 12
db-config add-field BKGLTRAN --num 6 --name AMOUNT      --type 6 --length 8  --offset 42
rem (type 0=STRING, 6=MONEY, 1=INT, 3=DATE, 4=TIME — see btr-import reference)

rem Verify the schema looks right
db-config show BKGLTRAN

rem Dry-run to check record counts before touching SQL Server
btr-import import-dir --dry-run G:\data

rem Create tables and import
btr-import import-dir --create G:\data
```

---

### Checking progress and re-importing

```bat
rem Preview without inserting anything
btr-import import-dir --dry-run G:\data

rem Import a single file
btr-import import G:\data\BKGLTRAN.B

rem Re-import (wipe and reload)
btr-import import --truncate G:\data\BKGLTRAN.B

rem Check the .B file header before importing
btr-import info G:\data\BKGLTRAN.B
```

Tables not in `wxbtrv.db` are skipped with a warning. Track migration
progress with `db-config`:

```bat
db-config migration-status
db-config mark-migrated BKGLTRAN --rows 15432 --server 10.0.0.5 --target-db GCanada
db-config clear-migrated BKGLTRAN
```
